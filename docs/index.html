AFFORD-Bench

240 physical manipulation tasks on a simulated Franka Panda across 8 domains, with 7-D actuator motor torques (τact), contact force telemetry, and paired counterfactual dynamic shift suites.

Every instruction names only simulated objects and is checked as a conjunction of physical goals, in order. A placed object must be released, supported, upright, and at rest within 2–8 mm of its goal. Grasping is frictional; nothing is welded or snapped into place.

Dynamic Robustness Gap

Same Past. Changed Present.

Conventional benchmarks only evaluate static variation before the robot acts. AFFORD-Bench formalizes mid-trajectory object displacement into paired Base and Dynamic suites across D1–D8.

Static Robustness (L1–L5)

The shift is visible before action begins.

Shift (t=0) → Reset → Observe → Act

Traditional OOD suites test generalization from a shifted initial scene layout. The policy plans from t=0 with full knowledge of the displaced objects.

⇒
Dynamic Robustness (Paired Suites)

The world shifts after the policy commits.

Reset → Act Prefix a0:t* → Displace (±3 cm) → Adapt

Both arms share the exact initial state, random seed, and executed prefix a0:t*. At trigger t*, the manipulated workpiece is displaced mid-trajectory, isolating online reactive adaptability.

Crucial Competitive Edge

Beyond Pixels: Physical Torque & Contact Safety

Unlike purely kinematic benchmarks (such as LIBERO-MAX, which lack all force and torque channels), AFFORD-Bench logs complete 7-D actuator motor torques τact and 3-D contact force vectors Fcontact throughout every episode.

When an online disturbance causes a trajectory error, kinematic benchmarks may score a violent collision or mechanical stall as "success" if the parts eventually slide into place. AFFORD-Bench enforces Compliant Dynamic Success: a policy must solve the goal while strictly respecting cobot safety envelopes.

Leaderboard

A result enters this table only with its per-episode log from scripts/evaluate_policy_suite.py (seeds, checkpoint hash, code version). The oracle reads the true object poses, so its row bounds what is solvable rather than predicting learned performance.

Tasks

210 tasks in 7 domains over six workcells. Each task is a conjunction of goal predicates; long-horizon tasks chain up to six goals. Click a row for its goals.

Perturbation suites

Suites are paired: an evaluation seed gives the same layout in L1, L3, L4, and Color, and the same layout in L2 and L5, so a drop measures the perturbation, not a new scene.

Oracle ceiling

Oracle success (%) per domain and suite in the task validation run: what each suite can ask of a learned policy.

Guarantees

  • Every episode completes all goals of its task within the task's step budget, from a sampled start.
  • Each file records the code, simulator, and asset versions and the command that produced it.
  • An episode-level validator checks every demonstration; replays of the recorded actions reproduce the recorded states exactly.
  • Converters export LeRobot and RLDS.
